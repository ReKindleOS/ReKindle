Kindle add-on · v1.0.0

ReKindle, without the Kindle in the way.

This add-on runs ReKindle on a jailbroken Kindle with the Kindle interface and browser chrome completely out of the way. There is no address bar and no status bar, but ReKindle keeps its normal framed layout: the desktop and app windows stay their designed size instead of stretching to fill the panel.

Read this before you jailbreak

Jailbreaking is a process, not an app. It can go wrong, it voids warranties, and it is not reversible with a normal uninstall. Follow the KindleModding jailbreak wizard for your exact model and firmware. Do not follow an old video or a random download.

Jailbreaking is not piracy. It does not make books free, and this add-on does not touch Amazon content or your account.

What you need

A supported Kindle Firmware 5.16.4 or newer. Check Settings → Device Options → Device Info. Older Kindles use the WebKit browser and cannot run this launcher.
A jailbreak with scriptlets A current jailbreak installs the Universal Hotfix, which makes .sh files in documents appear in your library. If other scriptlets work, you are ready.
Wi-Fi ReKindle is a web app, so the Kindle needs a connection for the first load. A USB cable is only needed for the ZIP route.

Install on this Kindle (KPM)

Amazon's stock browser rejects .sh and .txt downloads as "Invalid file type". The reliable no-computer route is KPM, the package manager included with current WinterBreak / SpringBreak jailbreaks. KPM downloads with the shell, so the browser file-type filter is not involved.

In the Kindle search bar, run these one at a time:

;kpm add-repo https://rekindle.ink/downloads/kpm/repo.json
;kpm update
;kpm install rekindle-fullscreen

The two scriptlets are copied into documents; open the library and tap ReKindle Fullscreen. If ;kpm is not recognised, your jailbreak does not include KPM — use the ZIP instead. KPM reference: kindlemodding.org/kindle-dev/kpm.

Download ZIP (USB) Direct .sh (may be blocked) Direct .txt (may be blocked)

Short links: rekindle.ink/kindle.sh / rekindle.ink/kindle.txt · Recovery: ReKindleStop.sh · Checksums: SHA256SUMS.txt

Why the direct links fail: the browser checks the saved filename/type, so renaming the URL or serving a .txt copy cannot bypass it. Direct download only works on firmware with the file-type restriction removed. KPM or USB is the supported route.

Install in four steps

  1. Jailbreak the Kindle

    Use the jailbreak wizard. It picks the current method for your model and firmware. When it is done, follow Prevent automatic updates so Amazon does not remove the jailbreak.

    Install the Universal Hotfix if your jailbreak did not already do it. Scriptlets are the install format used here; the scriptlet documentation explains how they work.

    You do not need KUAL. KUAL is obsolete on current firmware and does not work. If an old guide tells you to install KUAL first, it is out of date. Use the wizard and the scriptlet system instead. Jailbreak methods change as Amazon ships updates, which is why this guide links to the maintained wizard rather than repeating command sequences that go stale.

  2. Install the launcher

    KPM (no computer, recommended): run the three commands from the box above. KPM is included with current WinterBreak / SpringBreak jailbreaks. It downloads the package over the network with the shell and copies ReKindle.sh and ReKindleStop.sh into documents. If ;kpm is not recognised, use the ZIP.

    With a computer: download the ZIP, connect the Kindle over USB, and copy the documents folder from the ZIP into the Kindle's root folder. Merge it with the existing documents folder when asked. Eject the Kindle.

    Direct download: the stock browser reports Invalid file type for .sh and .txt, so do not rely on it unless your firmware has the browser's file-type restriction removed. KPM and USB are the supported routes.

  3. Open ReKindle Fullscreen

    In the Kindle library, search for ReKindle Fullscreen (it may be under Docs or Recent). Tap it. The screen will go blank for a few seconds while the Kindle interface stops, then ReKindle opens.

    If nothing happens, read the troubleshooting table below before trying again.

  4. Use ReKindle, then press power to leave

    Log in if you want cloud sync. Everything works as usual, just larger. To return to your library, press the power button once. The browser closes and the Kindle interface restarts.

Do not unplug or force-restart while it is starting

The launcher stops the Kindle GUI first, then starts the browser. If you interrupt that hand-off, you may see a blank screen for a few seconds. Press the power button once and wait; if the Kindle does not recover, hold power until it reboots.

How it works

Tap the scriptlet
→
Kindle GUI stops
→
Chromium opens ReKindle
Press power
→
Browser closes
→
Kindle GUI returns

The launcher stops lab126_gui, launches the stock /usr/bin/chromium/bin/kindle_browser with the same low-end flags the Kindle browser uses (JIT disabled, low-memory mode, grayscale), and opens rekindle.ink. It watches the power button and restores the GUI on exit. It does not modify the root filesystem, install a daemon, or run at boot.

The launcher only removes the Kindle interface and browser chrome. ReKindle itself is unchanged: the dashboard keeps its desktop frame and apps open in their normal System 7 windows. Nothing is stretched to the edges.

Supported devices

Device / firmware Fullscreen launcher What to do
Kindle on firmware 5.16.4+ (Chromium) Yes Use this guide. The launcher checks for the Chromium binary before it stops anything.
Kindle on firmware below 5.16.4 (WebKit) No Use rekindle.ink normally. Enable Default Fullscreen in Settings to reclaim the app frame, but the Kindle UI stays visible.
Kobo, Boox, Android e-readers Not needed Use the browser, or add ReKindle to the home screen.

If something goes wrong

Symptom What to do
"Invalid file type" when downloading .sh or .txt. Expected on stock firmware. Amazon's browser only allows book formats and checks the saved filename, so a .txt URL cannot bypass it. Use KPM (above) or the ZIP over USB.
Nothing happens when I tap ReKindle Fullscreen. Check firmware is 5.16.4+. Open /mnt/us/rekindle-fullscreen.log over USB. If the log says the Chromium browser is missing, this Kindle cannot run the launcher.
It opens, then drops back to the library. The browser could not start. Check the log and confirm the file is in /mnt/us/documents/ReKindle.sh. Re-download the ZIP if the file is truncated.
Blank screen, or the Kindle UI is gone. Press the power button once and wait up to 15 seconds. If nothing changes, hold power until the Kindle reboots. Then run ReKindle Stop from the library.
Text is too small or too large. Use Settings → Scale in ReKindle. For the launcher itself, create /mnt/us/rekindle-fullscreen.conf from the included example and set DSF to 1, 1.5 or 2. If the page is offset or leaves a blank strip at the top, also set CORD="0,0".
The page is rotated or clipped. Set Settings → Rotation to 0° while using fullscreen. The launcher expects the normal portrait layout; ReKindle's 90°/270° rotation is not supported in this mode.
The screen goes to sleep while ReKindle is open. The launcher disables the screensaver while it runs. If the device still sleeps, press power to wake it, then press power once more to exit cleanly.
The Kindle UI does not come back after pressing power. Run ReKindle Stop from the library. If the library is not visible, hold power until the Kindle reboots; the launcher does not change boot files, so a reboot is safe.
No internet. Connect to Wi-Fi before launching. The launcher turns Wi-Fi on if it is off, but it cannot join a network for you.

Uninstall

  1. If you installed with KPM, run ;kpm uninstall rekindle-fullscreen in the search bar. Otherwise delete documents/ReKindle.sh, documents/ReKindleStop.sh and documents/ReKindleCover.png from the Kindle (long-press in the library, or use USB).
  2. Delete /mnt/us/rekindle-fullscreen.log and /mnt/us/rekindle-fullscreen.conf if you created them.

Nothing else was installed. Your jailbreak, KUAL/KPM, books and Amazon account are untouched.

Safety, privacy and the fine print

  • No system changes. The launcher stops and starts the Kindle GUI and runs the stock browser binary. It writes only to /mnt/us (the USB-visible partition) and /tmp.
  • Recovery is a reboot away. If everything is stuck, hold the power button until the Kindle restarts. Because no boot files are changed, the device comes back normally.
  • Your ReKindle account is unchanged. The launcher opens the same site; login, sync and privacy behave exactly as they do in a normal browser.
  • Jailbreak support is community support. ReKindle can explain this add-on, but jailbreak problems belong with KindleModding and the model-specific guides.
