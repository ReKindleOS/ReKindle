Kindle add-on · v1.2.1 · Highly experimental

ReKindle, without the Kindle in the way.

This add-on stops the Kindle interface, mounts the stock Chromium image, and launches Chromium as the framework user on rekindle.ink. There is no address bar and no status bar, but ReKindle keeps its normal framed layout: the desktop and app windows stay their designed size instead of stretching to fill the panel.

Highly experimental - not a supported feature

This add-on is a community experiment, not something ReKindle supports. It has been tried on very few Kindle models and firmware versions, it changes how the device starts its browser, and a failed launch can leave the Kindle stuck until you reboot it. Do not install it on a Kindle you depend on.

Nothing in ReKindle requires it: a bookmark works on every supported device. If you are not comfortable recovering the Kindle yourself, stop here and keep using the normal browser.

Read this before you jailbreak

Jailbreaking is a process, not an app. It can go wrong, it voids warranties, and it is not reversible with a normal uninstall. Follow the KindleModding jailbreak wizard for your exact model and firmware. Do not follow an old video or a random download.

Jailbreaking is not piracy. It does not make books free, and this add-on does not touch Amazon content or your account.

What you need

A supported Kindle Firmware 5.16.4 or newer. Check Settings → Device Options → Device Info. Older Kindles use the WebKit browser and cannot run this launcher.
A jailbreak with scriptlets A current jailbreak installs the Universal Hotfix, which makes .sh files in documents appear in your library. If other scriptlets work, you are ready.
USB or kterm USB with the ZIP is the reliable install route. No computer? Install kterm through KPM and run the repo commands inside the terminal. ReKindle still needs Wi-Fi for its first load.

Install from a computer

This is the reliable route. Download the ZIP, unzip it, and copy the documents folder into the Kindle's root folder. The two scriptlets, the cover and the config example are all inside.

Short links: rekindle.ink/kindle.sh / rekindle.ink/kindle.txt · Checksums: SHA256SUMS.txt

Why not KPM directly from the search bar? Amazon's scriptExecutor only accepts letters, numbers, spaces, /, - and _ in ; commands. Any URL contains . or :, so ;kpm add-repo … is silently rejected and returns to Home. This is a known KPM limitation, not a repo error.

How it opens: v1.2.1 mirrors Amazon's browser launcher. It mounts /usr/bin/chromium.sqsh at /usr/bin/chromium when needed, then runs kindle_browser as the framework user with Amazon's 5.19.6 flags (--disable-xi2, --force-gpu-mem-available-mb=64, no --no-sandbox/--single-process). The Kindle GUI is restarted when you exit.

No computer? Use kterm. The search bar can install kterm because ;kpm install kterm has no URL. Open kterm, then run these as normal shell commands:

kpm add-repo https://rekindle.ink/downloads/kpm/repo.json
kpm update
kpm install rekindle

If kpm is not in the PATH, use /var/local/kmc/bin/kpm. The short URL https://repo.rekindle.ink serves the same manifest. KPM reference: kindlemodding.org/kindle-dev/kpm.

Direct browser downloads: stock firmware reports Invalid file type for .sh and .txt. Those buttons only work if the browser's file-type restriction has been removed.

Install in four steps

  1. Jailbreak the Kindle

    Use the jailbreak wizard. It picks the current method for your model and firmware. When it is done, follow Prevent automatic updates so Amazon does not remove the jailbreak.

    Install the Universal Hotfix if your jailbreak did not already do it. Scriptlets are the install format used here; the scriptlet documentation explains how they work.

    You do not need KUAL. KUAL is obsolete on current firmware and does not work. If an old guide tells you to install KUAL first, it is out of date. Use the wizard and the scriptlet system instead. Jailbreak methods change as Amazon ships updates, which is why this guide links to the maintained wizard rather than repeating command sequences that go stale.

  2. Install the launcher

    With a computer (recommended): download the ZIP, connect the Kindle over USB, and copy the documents folder from the ZIP into the Kindle's root folder. Merge it with the existing documents folder when asked. Eject the Kindle.

    No computer, with kterm: install kterm with ;kpm install kterm (the search bar allows this because there is no URL), open kterm, and run the three kpm commands from the box above. KPM downloads the package with the shell and copies the scriptlets into documents.

    Direct download: the stock browser reports Invalid file type for .sh and .txt, so do not rely on it unless your firmware has the browser's file-type restriction removed.

  3. Open ReKindle

    In the Kindle library, search for ReKindle (it may be under Docs or Recent). Tap it. The screen goes blank for a few seconds while the Kindle interface stops, then ReKindle opens in Chromium.

    If nothing happens, read the troubleshooting table below before trying again.

  4. Use ReKindle, then press power to leave

    Log in if you want cloud sync. Everything works as usual, just larger. To return to your library, press the power button once. The browser closes; the Kindle interface was never stopped, so nothing needs to restart.

If the browser does not appear

The launcher stops the Kindle GUI before starting Chromium. If the browser fails, power the Kindle off and on; the launcher has no boot hooks and the GUI comes back normally. Open ReKindle Error from the library for the reason.

The launcher stops lab126_gui, mounts chromium.sqsh if it is not already mounted, and launches kindle_browser as framework with Amazon's own low-end flags. It watches the power button and restarts the GUI on exit. It does not modify the root filesystem, install a daemon, or run at boot.

ReKindle itself is unchanged: the dashboard keeps its desktop frame and apps open in their normal System 7 windows. Nothing is stretched to the edges.

Supported devices

Device / firmware Browser launcher What to do
Kindle on firmware 5.16.4+ (Chromium) Yes Use this guide. The launcher opens the stock browser; it does not need a direct Chromium path.
Kindle on firmware below 5.16.4 (WebKit) No Use rekindle.ink normally. Enable Default Fullscreen in Settings to reclaim the app frame, but the Kindle UI stays visible.
Kobo, Boox, Android e-readers Not needed Use the browser, or add ReKindle to the home screen.

If something goes wrong

Symptom What to do
;kpm add-repo … returns to Home and the repo list stays empty. Amazon's search bar rejects . and : in ; commands, so a URL can never reach KPM. Use the ZIP, or install kterm with ;kpm install kterm and run kpm add-repo inside it. This is a known KPM limitation.
"Invalid file type" when downloading .sh or .txt. Expected on stock firmware. Amazon's browser only allows book formats and checks the saved filename, so a .txt URL cannot bypass it. Use KPM (above) or the ZIP over USB.
Nothing happens when I tap ReKindle. Check firmware is 5.16.4+. Open ReKindle Error or /mnt/us/rekindle-fullscreen.log over USB. The log records whether chromium.sqsh mounted and which browser path was used.
It opens, then drops back to the library. The browser could not start. Check the log and confirm the file is in /mnt/us/documents/ReKindle.sh. Re-download the ZIP if the file is truncated.
ReKindle launches but stays on a white screen. Press power once to exit, then open ReKindle Log from the library. The log records the mounted Chromium path and Chromium stderr. If the device is unresponsive, hold power until it reboots.
Blank page, or the Kindle UI is gone. Press the power button once and wait up to 15 seconds. If nothing changes, hold power until the Kindle reboots. The launcher changes no boot files.
Text is too small or too large. Use Settings → Scale in ReKindle. The launcher no longer has its own scale setting; it uses the browser's normal page scale.
The page is rotated or clipped. Set Settings → Rotation to 0° while using fullscreen. The launcher expects the normal portrait layout; ReKindle's 90°/270° rotation is not supported in this mode.
The screen goes to sleep while ReKindle is open. The launcher disables the screensaver while it runs. If the device still sleeps, press power to wake it, then press power once more to exit cleanly.
The Kindle UI is unresponsive. Hold power until the Kindle reboots. The launcher changes no boot files; the GUI restart is part of its normal exit path.
No internet. Connect to Wi-Fi before launching. The launcher turns Wi-Fi on if it is off, but it cannot join a network for you.

Uninstall

  1. If you installed with KPM, run ;kpm uninstall rekindle in the search bar. Otherwise delete documents/ReKindle.sh and documents/ReKindleCover.png from the Kindle (long-press in the library, or use USB).
  2. Delete /mnt/us/rekindle-fullscreen.log and /mnt/us/rekindle-fullscreen.conf if you created them.

Nothing else was installed. Your jailbreak, KUAL/KPM, books and Amazon account are untouched.

Safety, privacy and the fine print

  • Highly experimental. This is an add-on maintained in the community, with limited real-device testing. Treat any failure as possible: keep a USB cable, a computer and the troubleshooting table above within reach before you install it.
  • No system changes. The launcher stops and restarts the Kindle GUI and mounts chromium.sqsh temporarily. It writes only to /mnt/us (the USB-visible partition).
  • Recovery is a reboot away. If everything is stuck, hold the power button until the Kindle restarts. Because no boot files are changed, the device comes back normally.
  • Your ReKindle account is unchanged. The launcher opens the same site; login, sync and privacy behave exactly as they do in a normal browser.
  • Jailbreak support is community support. ReKindle can explain this add-on, but jailbreak problems belong with KindleModding and the model-specific guides.
