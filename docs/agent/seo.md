# SEO & Search Console

Read this before adding a page, touching `<head>` markup, editing `sitemap.xml` /
`robots.txt`, or when Search Console reports coverage problems.

## The 2026-11-10 cleanup (what Search Console said)

`rekindle.ink-Coverage-2026-11-10.zip` (property `rekindle.ink`, sitemap "All known
pages") reported 862 URLs not indexed, 272 indexed:

| Reason | Pages | Root cause | Status |
| :--- | ---: | :--- | :--- |
| Duplicate without user-selected canonical | 209 | no canonical anywhere; one page reachable as `/x`, `/x.html`, `/X`, `/x/`, `lite./x`, `legacy./x` | fixed |
| Page with redirect | 162 | Pages 308s `/x.html` → `/x`; Google had discovered `.html` URLs | expected, informational |
| Not found (404) | 94 | historical; nothing 404s today because every unknown URL returned the home page | fixed (see below) |
| Soft 404 | 11 | no `404.html`, so unknown URLs served the dashboard with HTTP 200 | fixed |
| Blocked due to other 4xx | 8 | none reproducible today | monitor |
| Excluded by `noindex` tag | 4 | `/moderation` (and host copies) was submitted in the sitemap while noindex | fixed |
| Server error (5xx) | 2 | none reproducible; all 140 sitemap URLs return 200 | monitor |
| Crawled – currently not indexed | 86 | thin/client-rendered pages + the duplicates above | improved |
| Discovered – currently not indexed | 15 | crawl budget | improved |

Performance for 31 Oct–6 Nov 2026 was 1,021 clicks / 9,665 impressions (Mobile
11.47% CTR at avg position 2.87, Desktop 7.96% at 9.32). The missing meta
descriptions are why desktop CTR was that low: Google had to invent every snippet.

## Root cause 1: Cloudflare Pages' SPA fallback

From the Pages docs ([Serving Pages](https://developers.cloudflare.com/pages/configuration/serving-pages/)):

> If your project does not include a top-level `404.html` file, Pages assumes that you
> are deploying a single-page application... Pages' default single-page application
> behavior matches all incoming paths to the root (`/`).

Before this fix, `curl https://rekindle.ink/zzz-not-a-page` returned **HTTP 200** with
the dashboard (109,656 bytes), and so did `/u/` — a URL that was not in `sitemap.xml`
and had no page behind it, yet collected **2,231 impressions** in Search Console. That
one missing file produced most of the "duplicate" and "soft 404" rows above.

`404.html` (repo root) is now copied into `_deploy/main`, `_deploy/lite` and
`_deploy/legacy` by the normal build copy, which switches all three projects back to
"404-page" handling. Two rules for it:

* **It must not load scripts.** No `theme.js`, no Firebase, no service worker. It has to
  render on a stock Kindle with no network beyond the HTML itself, so the CSS is inline
  and the page is a plain System 7 window.
* **It is `noindex, follow`** and is excluded from `sitemap.xml`. Never add `noindex`
  pages to a robots.txt `Disallow` instead — blocking the crawl stops Google reading the
  noindex, which produces "Indexed, though blocked by robots.txt".

Do not add `/* /index.html 200` to `_redirects`: that re-creates the same soft-404
machine deliberately.

## Root cause 2: no per-page metadata

Every page is a separate app, but in November 2026 **zero** pages had a canonical, a
meta description, an Open Graph tag or a `<h1>` with text (the app name lived in a
`.title-text` `<span>`, which carries no heading semantics for crawlers or screen
readers). 140 pages had no description at all.

The fix is one pipeline, and `npm test` enforces all of it:

```
scripts/seo-pages.js   ← single source of truth (name, tag, type, summary, noindex)
        │
        ├── scripts/seo-inject.js   writes the HTML: <title>, description, robots,
        │                           canonical, OG/Twitter, JSON-LD, screen-reader <h1>
        │
        ├── scripts/generate-sitemap.js   same table → which URLs get submitted
        │
        └── scripts/test-seo.js     fails the build if any of the above drifts
```

### Adding a page (checklist)

1. Add an entry to `scripts/seo-pages.js`:
   ```js
   'myapp': { name: 'My App', tag: 'What it does in 6 words', type: 'game', summary: 'One sentence. Free on Kindle...' },
   ```
   `type` is `game | tool | reading | social | media | health | info | system`. `system`
   pages (login, settings, probe, moderation) are private: set `noindex: true`.
2. `node scripts/seo-inject.js` — writes the block into the new file (and fixes any
   other page whose table entry changed).
3. `node scripts/test-seo.js` — must pass.

### What the generated block looks like

```html
<!-- seo:begin (generated by scripts/seo-inject.js - edit scripts/seo-pages.js) -->
<meta name="description" content="...">
<meta name="robots" content="index, follow, max-image-preview:large">
<link rel="canonical" href="https://rekindle.ink/sudoku">
... og:*, twitter:* ...
<style>.rk-seo-h1{position:absolute;width:1px;height:1px;...clip:rect(0 0 0 0)}</style>
<script type="application/ld+json">{"@graph":[{"@type":"WebApplication",...},{"@type":"BreadcrumbList",...}]}</script>
<!-- seo:end -->
```

and, when the page has no heading with text, in `<body>`:

```html
<!-- seo:h1 --><h1 class="rk-seo-h1">Sudoku</h1><!-- /seo:h1 -->
```

**Never hand-edit inside those markers, and never hand-add a `description`, `robots`,
`canonical`, `og:*` or `twitter:*` tag.** The injector strips hand-written copies, so a
manual tag silently disappears the next time it runs. Edit the table instead.

Why the `<h1>` is visually hidden: the visible heading is `.title-text` inside the
title bar, and converting that `<span>` to an `<h1>` across 122 pages would drag
default `h1` margins into a layout that is tuned per page for e-ink. The clipped `<h1>`
gives screen readers and crawlers the heading with zero layout risk. It is not
"hidden text" in the spam sense — it is the accessible page heading.

### Titles and descriptions

* Titles: `Name – short tag | ReKindle`, **≤ 60 chars**, unique. Long titles get
  truncated in results; duplicate titles make Google pick its own.
* Descriptions: `summary + category tail`, **60–160 chars**, unique. They are not a
  ranking factor, but an empty one is why the desktop CTR sat at 7.96%.
* A `<title data-i18n="...">` keeps its attribute: `js/i18n.js` only rewrites it when the
  active locale has the key, so English keeps the SEO title and other languages keep
  their translation.

## Canonical policy across the three hosts

`rekindle.ink` is canonical. `lite.` and `legacy.` are the same pages for older
browsers, and *every* build writes `https://rekindle.ink/<page>` into the canonical, so
all six variants of a page (`/x`, `/x.html`→308, `/X`, `/x/`→308, `lite./x`,
`legacy./x`) point at one URL. Old devices still reach the right build: `/` detects
Kobo/Mesquite by UA and redirects client-side.

`/index_old` is `noindex` on the main host (it is a duplicate dashboard kept for
`?layout=old` users), **but Lite and Legacy serve it as their `/`**. Build step 2.5
therefore re-renders its head with the home page's metadata before writing it to
`_deploy/{lite,legacy}/index.html`; copying it verbatim would have given both alternates
a noindex homepage canonicalised to `/index_old`.

## sitemap.xml

* Generated by `scripts/generate-sitemap.js` into each deploy target (three hosts, each
  listing its own URLs).
* Excludes anything marked `noindex` in `scripts/seo-pages.js`, `404.html`, and
  `_`-prefixed partials. Sitemap and `<meta robots>` can no longer disagree.
* `<lastmod>` is each file's **last commit date** (`git log --pretty=format:%cs
  --name-only`, one call per build), falling back to mtime outside git. A lastmod that
  is always "today" is a signal Google learns to ignore — this is why the old generator
  (which used `stat().mtime`, i.e. build time in CI) was replaced.
* That needs real history: `.github/workflows/deploy.yml` checks out with
  `fetch-depth: 0`. With the default depth-1 clone every file looks modified in the same
  commit and every lastmod collapses to today again.
* `_headers` caps `/sitemap.xml` and `/robots.txt` at `max-age=3600`; everything else
  non-HTML is edge-cached for a week, which is too stale for a crawler signal.

## robots.txt

`build-automation.js` step 9.1 rewrites the `Sitemap:` line per target
(`rekindle.ink`, `lite.rekindle.ink`, `legacy.rekindle.ink`). The source `robots.txt` is
copied verbatim into all three deploys, so before this pass the alternates advertised
`https://rekindle.ink/sitemap.xml` — a cross-host `Sitemap:` declaration, which Google
ignores, leaving both alternates with no sitemap at all.

Cloudflare prepends its managed "content signals" block (AI-training crawlers) at the
edge; the file in the repo is what follows it. Do not add `Disallow` rules for
noindex pages (see above).

## Verification after a deploy

1. `curl -sI https://rekindle.ink/zzz-not-a-page` → **404** (was 200 + dashboard).
2. `curl -s https://rekindle.ink/sudoku | grep canonical` → `https://rekindle.ink/sudoku`.
3. `curl -s https://lite.rekindle.ink/robots.txt | grep Sitemap` → the lite host.
4. `curl -s https://rekindle.ink/sitemap.xml | grep -c '<url>'` → 137.
5. Search Console → Sitemaps → resubmit `sitemap.xml`, then "Validate fix" on each
   coverage report. Canonical/soft-404 changes take a recrawl to show up; expect weeks.
6. Rich results: https://search.google.com/test/rich-results?url=https://rekindle.ink/ —
   expect `WebSite` + `WebApplication` + `Breadcrumbs`.

## Local build gotcha (Dropbox)

This repo usually lives inside a Dropbox folder. Dropbox turns the synced `_deploy`
directory into `_deploy (Selective Sync Conflict N)` copies beside it. Those are only
`_deploy/`-prefixed, so the old copy loop copied a 320 MB stale deploy tree *into*
`_deploy/main`, recursed through its `openmoji/` files, and died with

```
ENOENT: no such file or directory, chmod '_deploy/main/_deploy (Selective Sync Conflict 2)/main/...'
```

Sometimes it failed differently (`ENOENT: open '_deploy/lite/pet.html'`) because Dropbox
was moving files out from under the build. Fixes, all in place:

* `build-automation.js` skips any `_deploy*` entry and any name matching
  `Selective Sync Conflict` / `conflicted copy` / `CASE CONFLICT` when copying;
* `.gitignore` ignores `/_deploy*/` so the copies are never committed;
* if a build fails this way, delete the conflict folders
  (`rm -rf "_deploy (Selective Sync Conflict"*`) and build again — or build outside
  Dropbox entirely (`rsync` the tree to `/tmp` and symlink `node_modules`).

CI is unaffected: GitHub Actions has no Dropbox.

## Things that are deliberately *not* done

* **hreflang / per-language URLs.** The UI language is client-side (`?lang=` is a QA
  override, not a route), so there is one URL per page. Canonical without the query
  string is the correct signal; real hreflang would need localized URLs and a routing
  change across 140 pages.
* **`Disallow`ing `lite.`/`legacy.`.** They must stay crawlable so their canonical is
  seen; blocking them would keep the duplicates in the index.
* **Demoting the About-modal `<h1>` in `index_old.html`.** That file carries two
  `<h1>`s: the visible `.os-title` and one inside `#about-modal`. Two headings are valid
  HTML5 and are not a ranking signal, and `scripts/test-seo.js` enforces "one `<h1>` with
  text" on indexable pages only (`index_old` is noindex). Lite and Legacy serve that
  markup at `/` and so have two as well — left alone deliberately, because re-tagging a
  heading on the build that old Kindles actually use risks a rendering regression for a
  non-issue.
* **Trying to make "Page with redirect" disappear.** Pages' automatic
  `/x.html` → `/x` 308 is correct server behaviour. 162 is Google's backlog of `.html`
  URLs from before the sitemap was cleaned up.
* **Injecting an `aggregateRating`.** There are no real ratings to publish; inventing
  them is a structured-data violation.
